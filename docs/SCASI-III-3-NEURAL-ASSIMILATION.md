# SCASI III.3 — Neural Knowledge Assimilation

**Status:** additive research experiment, not a proven model improvement or measured Effective Intelligence Multiplier (EIM).

## Testable hypothesis

Validated condensed knowledge introduced *during native COG-FU weight training* might improve held-out generalization even when that knowledge is absent from subsequent inference. III.3 distinguishes real model-weight learning from external calculator or retrieval augmentation.

## Three arms and controls

- **Original**: untouched parent COG-FU checkpoint.
- **Control**: same parent checkpoint fine-tuned on reviewed input/output examples with a neutral training-only system message.
- **Assimilated**: same parent checkpoint fine-tuned on the same input/output examples with a validated symbolic rule in the training-only system message.

Both continuation arms use the native NTSA-X `cog_fu_train.train` entrypoint, same initialization, same labels and order, number of steps, seed and optimizer settings. Neutral control messages are padded to **exactly match the UTF-8 byte-token budget** of condensed training contexts. Both evaluation arms receive plain user questions **without** system hints, memory, or symbolic tool extensions. Two new checkpoint directories are created; the parent checkpoint remains unchanged.

This controls input size, *not* the different token distributions or semantic contents. Development validation used in rule selection is not a substitute for untouched held-out testing. At least three unique train input values and two unique validation values per skill are required, from disjoint sources. The test partition must be separately provided and cannot overlap training or validation input values.

## Prepare an experiment, no weights needed

```bash
python -m examples.experiment_scasi_iii3 \
  --examples /path/to/reviewed-examples.jsonl \
  --heldout /path/to/sealed-exam.jsonl \
  --workdir /path/to/new-preparation
```

Creates `control_train.jsonl`, `condensed_train.jsonl`, `validation.jsonl`, `manifest.json`, and `preparation.json`. The public toy data in `examples/fixtures` is useful for setup checks but **not** for scientific claims of generalization.

## Run actual native checkpoint learning and held-out evaluation

```bash
python -m examples.experiment_scasi_iii3 \
  --examples /path/to/reviewed-examples.jsonl \
  --heldout /path/to/private-sealed-exam.jsonl \
  --checkpoint /path/to/existing-cog-fu-checkpoint \
  --workdir /path/to/new-run-directory \
  --train --epochs 2 --batch-size 2 --device cpu --seed 42
```

Requires COG-FU `weights.pt` and `config.json` generated by NTSA-X. All stored files are additive and no existing output is overwritten. The benchmark produces three native-model arm reports, per-arm checkpoint hashes, parent hash, exact-match accuracy, Wilson 95% intervals, p50/p95/p99 response latency, per-question paired discordance, training wall time and parameter count. `eim` remains null until a real capability/compute comparison is independently established. PyTorch is used by the existing native trainer; no external teacher weights are downloaded.

## Example JSONL schemas

Reviewed samples use `SkillExample` records:

```json
{"skill_id":"calibration","input_value":3,"output_value":11,"partition":"train","source":"reviewed-train","reviewed":true}
```

Heldout samples use `HeldoutCase` records:

```json
{"prompt":"compute calibration 19","expected":"59","group":"sealed"}
```

All examples must be reviewed and rights-cleared before training. The sample fixtures included here are public and should never be mistaken for an independent exam. Results on this toy task are not evidence of broad reasoning, recursive intelligence improvement, negative physical latency or a 50–200× efficiency advantage.

## Testing

```bash
python -m unittest tests.test_scasi_iii_assimilation -v
python -m compileall -q ntsa_x/scasi_iii_assimilation.py examples/experiment_scasi_iii3.py
```

A native-COG-FU dataset-parser test runs when the real native PyTorch modules exist (in the repository's native CI stage) and skips in a minimal standard-library-only environment. Ordinary tests do not train weights or modify checkpoints.

Native CI also exercises an actual CPU COG-FU supervised gradient step using the condensed training context. It verifies nonzero gradients, changed finite model weights, and a no-overwrite preparation path. This is a gradient plumbing test only; no neural generalization is inferred until a real checkpoint is trained and scored on a sealed exam.
